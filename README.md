# metroscope

**수도권 지하철 관제실 화면, 근데 진짜 서울 지도 위에서, 3D로, 소리도 나는.**

네이버 지도가 "내가 어떻게 가지?"에 답한다면, metroscope는 **"지금 지하철 전체가 어떤 상태지?"**에 답합니다.

- 🗺️ **진짜 지도 위의 전 노선**: 1~9호선, 경의중앙·공항철도·경춘·수인분당·신분당·우이신설·서해·경강·신림선, GTX-A, 김포골드·의정부·용인·인천 1/2호선까지 24개 노선, 약 800개 역을 실제 좌표에 그립니다. 노선은 역 사이를 직선으로 잇지 않고 OpenStreetMap의 실제 선로 형상을 따라갑니다
- 🏙️ **3D 도시**: 기울어진 시점, 입체 건물, 지형 음영. 가까이 가면 열차가 선로를 따라 휘어지는 입체 차량으로 바뀝니다
- 📏 **배차 간격 시각화**: "배차 간격" 모드에서 열차 사이 구간을 간격에 따라 색칠합니다. 몰림(청록), 정상(초록), 넓음(주황), 공백(빨강). 방향별로 선로 양쪽에 나눠 그립니다
- 🚆 **열차 따라가기**: 열차를 누르면 행선지·현재 위치가 나오고, "따라가기"로 카메라가 열차를 쫓아갑니다
- 🎵 **소리 모드**: 화면 안에서 열차가 역에 도착할 때마다 음이 울립니다. 화면 위쪽일수록 높은 음, 좌우는 스테레오. 보고 있는 곳이 곧 악보입니다

## 실행

```bash
npm install
npm run dev
# http://localhost:3000
```

API 키 없이도 **시뮬레이션 모드**로 바로 돌아갑니다 (전 노선, 실제 선로 길이 기준 속도, 종점 회차).

### 실시간 데이터 연결

1. [서울 열린데이터광장](https://data.seoul.go.kr)에서 **실시간 지하철 인증키**를 발급받습니다
2. `.env.example`을 `.env`로 복사하고 `SEOUL_API_KEY`를 채웁니다
3. `realtimeStationArrival/ALL` **한 번 호출로 전 노선**의 열차를 받습니다 (약 3,000행, 2MB). 각 역의 "다음 도착 열차" 목록에서 열차마다 가장 최근·가장 정확한 행을 골라 위치를 정합니다. 진행 방향은 종착역 기준으로 판단하고, 순환선(2호선, 6호선 응암)은 행에 담긴 이전/다음 역 ID로 판단합니다. 공항철도는 이전/다음 역이 뒤바뀌어 오고, 일부 행은 미래 시각(`recptnDt`)이 찍혀 오는데 둘 다 보정합니다
4. 기본 `POLL_MS=75000`: 일일 한도 1,000회 기준, 운행 시간(05:30~01:00)에만 폴링해 하루 약 936회를 씁니다. 새벽엔 자동으로 쉬고 지도를 비웁니다. 업데이트 사이엔 브라우저가 열차를 다음 역 직전까지만 진행 방향으로 움직여 부드럽게 보이게 합니다
5. 서버가 한 번 받아 모든 접속자에게 SSE로 뿌리므로, 접속자가 늘어도 API 호출은 늘지 않습니다

김포골드·의정부·용인·인천 1/2호선은 실시간 API에 없어서 라이브 모드에선 노선만 그려지고 "실시간 미제공"으로 표시됩니다. API와 지도 데이터의 역 이름이 다르면 서버 로그에 `unknown station`이 찍힙니다. 그럴 땐 `server/lines.ts`의 `API_ALIASES`에 추가하세요.

## 노선 데이터 (`data/network.json`)

역 좌표와 선로 형상은 OpenStreetMap에서 미리 뽑아 저장소에 넣어 둡니다. 실행 중엔 외부 호출을 하지 않습니다.

```bash
npm run build:network              # scripts/.cache/osm.json이 있으면 재사용
npm run build:network -- --refresh # Overpass API에서 새로 받기
```

- 노선 정의는 `server/lines.ts`: 색, API `subwayId`, OSM 노선 이름, 그리고 **체인**(분기 없는 역 순서 경로)
- 체인은 경유역만 적으면 됩니다. 예: 2호선 본선 `["시청", "왕십리", "잠실", ...], loop: true`. 사이의 역은 OSM 정차 순서로 만든 역 그래프에서 채웁니다
- 급행 노선은 역을 건너뛰므로 제외하고, 그래도 섞여 들어온 "역 건너뛰기" 연결은 자동으로 걸러냅니다
- 역 사이 형상은 해당 노선의 선로 way 위에서 최단 경로로 찾습니다

## 배포 (Docker)

```bash
docker build -t metroscope .
docker run -d --name metroscope --restart unless-stopped \
  --env-file .env -p 127.0.0.1:3110:3000 metroscope
```

`.env`는 이미지에 포함되지 않으니 서버에 따로 두세요.

### 자동 배포

운영 서버는 cron으로 1분마다 `origin/main`을 확인해서, 새 커밋이 있으면 다시 빌드해 배포합니다 (서버의 `autodeploy.sh`).
`main`에 푸시하면 1~3분 안에 반영됩니다. 빌드가 실패하면 기존 버전이 그대로 돌고, 새 버전이 healthy가 안 되면 이전 커밋으로 롤백합니다. 개발 환경(로컬·클라우드 세션)은 키 없이 시뮬레이션 모드로 돌리면 실서버의 하루 호출 한도를 나눠 쓰지 않습니다.

## 구조

```
server/
  index.ts           Express + SSE 브로드캐스트, 야간 휴식
  lines.ts           노선 정의 (색, API id, OSM 이름, 체인 경유역), 역 이름 정규화
  network.ts         data/network.json 로드, 구간 길이·역 인덱스 헬퍼
  feeds/seoul.ts     realtimeStationArrival/ALL → 전 노선 열차 위치
  feeds/mock.ts      API 키 없을 때 쓰는 시뮬레이터
scripts/
  build-network.ts   OpenStreetMap → data/network.json
data/
  network.json       역 좌표, 체인별 역 순서와 선로 형상 (생성물, 커밋함)
web/                 빌드 없는 순수 JS (ES modules)
  app.js             지도, 레이어, 열차 애니메이션, 배차 간격, 상호작용
  basemap.js         어두운 베이스맵 스타일 (OpenFreeMap 벡터 타일 + 지형 음영)
  geo.js             선로 위 거리 ↔ 좌표 변환, 구간 자르기, 3D 열차 리본
  sound.js           Web Audio 도착음
```

지도 렌더링은 [MapLibre GL JS](https://maplibre.org)(npm 의존성, 서버가 `/vendor/maplibre-gl`로 제공), 베이스맵 타일은 [OpenFreeMap](https://openfreemap.org), 지형 음영은 공개 Terrarium DEM 타일입니다. 모두 키가 필요 없습니다.

## 알려진 한계

- API가 **역 단위**(진입/도착/출발/전역출발…)로만 위치를 줘서, 역 사이 위치는 추정값입니다
- 방향 판단은 2026-10-12 실데이터로 검증했습니다 (종착역과 일치 431/431, 2호선 순환 130/130). 노선별 API 특이사항이 바뀌면 다시 확인이 필요합니다
- 같은 선로를 공유하는 구간(예: 경의중앙·경춘선 회기~상봉)은 노선이 겹쳐 하나만 보입니다
- 체인이 바뀌는 분기역(예: 1호선 구로)에서는 배차 간격이 끊겨서 계산됩니다
- 경의중앙선 지평, 임진강·도라산 셔틀, GTX-A 성남역은 OSM 노선 데이터에 빠져 있어 지도에 없습니다 (해당 열차는 표시되지 않음)
